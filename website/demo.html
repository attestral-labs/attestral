The number behind scene two

The same detection, run across 390 popular MCP servers.

ATL-202 is not a demo trick. We pointed the same system-model detection at the 390 most popular open-source MCP server repositories (each at least 200 GitHub stars), scanning the launch configuration each repo documents. 233 shipped a config concrete enough to model. 76 of those, 32.6 percent, assemble the lethal trifecta in one agent session.

The number is stable and it reproduces: 32.7 percent at 222 repos, 32.6 percent at 390, and every trifecta finding re-fired identically on a clean re-scan. We were just as hard on our own noise. A naive "no auth" alarm fired on 48 percent of servers, and fell to 0.9 percent once the check understood the MCP spec's OAuth flow.

The loud per-server alarms washed out; the compositional finding survived. Deduped, documented launch configs; aggregate figures only, no server named. The one named example stays under coordinated disclosure until its window closes.

What you just watched

The loop, not a linter.

The critical finding never lived in any single file, and the runtime catch never required a signature update. Both came from the same place: a system model of what the agent can actually reach, kept honest from review to runtime.

Measure

Build the system model: components, edges, trust boundaries, from MCP configs, Terraform, and Kubernetes.

Catch

Deterministic design rules plus ML injection scoring, run on the model, so combination risks like ATL-202 exist to be found.

Enforce

The attested design compiles to a default-deny mcp-guard policy. Drift diffs the runtime against it and only ever narrows.

Attest

Findings live in a tamper-evident evidence chain. Waivers expire, reports are signed, auditors get the artifact.

Run it yourself

The tape is a recording, and it is pinned by tests.

Every input ships in the repo. Tape one's opening config is examples/first-run; the remediated config and the telemetry stream both tapes run on are examples/demo-tape, so each command in either tape replays from committed files. Two suites pin the recording to the live tool: the fixture-sync guard keeps the README counts matched to real scans, and tests/test_demo_tape.py asserts the tapes' on-screen claims, the clean scan, the exact three drift findings, and the sign/verify/tamper round trip.

The telemetry stream is demo-authored, and the tapes treat it as such. Everything computed over it is the tool's real output: the drift findings, the pushed lockdown and its hash-chained journal, the replay reconstruction, and the signed incident attestation, including the verification failure when one byte of the stream is edited. Every terminal frame is a byte-exact capture of attestral v0.20.0.

pip install attestral
attestral scan examples/first-run     # tape 001, scene 2, verbatim
cd examples/demo-tape && attestral compile .
attestral drift --remediate mcp-guard-policy.yaml runtime-events.jsonl
attestral incident --gen-key k --journal live-policy.yaml.journal.jsonl \
    mcp-guard-policy.yaml runtime-events.jsonl          # tape 002's evidence
attestral scan --local                # audit the MCP configs on this machine
